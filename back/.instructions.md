# Music Party Game — SpaceTimeDB Backend

## Overview

This backend runs entirely on **SpaceTimeDB**, eliminating the need for a traditional Node.js/Express server. SpaceTimeDB handles:
- Game state persistence and real-time sync
- Player room management and subscriptions
- Game logic via reducers (Rust stored procedures)
- HTTP proxy calls to Spotify API (server-side credentials)

The client connects directly to SpaceTimeDB via the TypeScript SDK, subscribes to relevant tables, and receives real-time updates.

---

## Architecture

```
┌─────────────┐
│   React     │
│   Client    │  <- Subscribes to SpaceTimeDB tables
│             │  <- Calls reducers (game actions)
└──────┬──────┘
       │
       │ SpaceTimeDB SDK
       │
┌──────▼─────────────────┐
│  SpaceTimeDB Instance  │
│                        │
│  ├─ Tables (Schema)    │ <- Persistent game state
│  ├─ Reducers           │ <- Game logic & Spotify proxy
│  └─ Auth/Access        │ <- Room-based subscriptions
│                        │
│  HTTP Egress ──────────┼──> Spotify Web API
│  (credentials kept     │    (search, preview URLs)
│   server-side)         │
└────────────────────────┘
```

**Why SpaceTimeDB?**
- Real-time multiplayer state sync without WebSocket boilerplate
- Automatic subscription filtering (players only see their room's data)
- Built-in auth primitives for room isolation
- Reducers handle both game logic and external API calls

## Database Schema

### Tables

#### `Room`
Represents a game room. One room per game instance.

```rust
#[derive(Table, Serialize, Deserialize)]
pub struct Room {
    #[primary_key]
    pub id: u64,
    
    pub host_id: u64,                    // Player ID of the room creator
    pub join_code: String,               // 6-char code (e.g., "ABC123")
    pub name: String,                    // Optional room name
    
    pub state: GameState,                // LOBBY, SEED_SELECTION, LISTENING, etc.
    pub current_round: u32,              // Round number
    pub current_hot_seat_id: Option<u64>, // Player ID of this round's hot seat
    
    pub seed_song_id: Option<u64>,       // Song ID of the current seed
    pub seed_prompt: Option<String>,     // e.g., "songs with cities in the title"
    
    pub created_at: i64,                 // Unix timestamp
    pub state_changed_at: i64,           // When the current state started
}

pub enum GameState {
    Lobby,
    SeedSelection,
    Listening,
    Submission,
    Voting,
    Results,
}
```

**Lifecycle:**
- Created when a player starts a room
- State transitions driven by reducers and timers (client-side or via scheduled reducers)
- Deleted after game ends (or kept for stats/replay)

---

#### `Player`
A person in a room.

```rust
#[derive(Table, Serialize, Deserialize, Clone)]
pub struct Player {
    #[primary_key]
    pub id: u64,
    
    pub room_id: u64,                    // Foreign key to Room
    pub name: String,                    // Display name
    pub score: u32,                      // Cumulative points
    
    pub is_host: bool,                   // Can start game
    pub is_ready: bool,                  // Ready to play (only relevant in LOBBY)
    pub is_connected: bool,              // Currently online
    
    pub joined_at: i64,                  // Unix timestamp
}
```

**Lifecycle:**
- Created when a player joins a room
- Deleted when they leave or game ends
- Score incremented after each round

---

#### `Song`
A song submitted by a player in a round.

```rust
#[derive(Table, Serialize, Deserialize, Clone)]
pub struct Song {
    #[primary_key]
    pub id: u64,
    
    pub room_id: u64,                    // Foreign key
    pub round_number: u32,               // Which round
    pub submitter_id: u64,               // Who submitted (foreign key to Player)
    
    pub spotify_id: String,              // Spotify track ID
    pub name: String,                    // Track name
    pub artist: String,                  // Artist(s)
    pub album_cover_url: String,         // Album art
    pub preview_url: String,             // 30-second MP3 URL
    
    pub is_seed: bool,                   // True if this is the hot seat's seed song
    pub submitted_at: i64,               // When it was submitted
}
```

**Lifecycle:**
- Seed song created in SEED_SELECTION state
- Regular submissions created in SUBMISSION state
- Deleted when round ends (or kept for replay)

---

#### `Rating`
A vote on a song.

```rust
#[derive(Table, Serialize, Deserialize, Clone)]
pub struct Rating {
    #[primary_key]
    pub id: u64,
    
    pub room_id: u64,
    pub round_number: u32,
    pub song_id: u64,                    // Foreign key to Song
    pub rater_id: u64,                   // Who voted (foreign key to Player)
    
    pub score: u8,                       // 1–10
    pub rated_at: i64,                   // When the rating was submitted
}
```

**Constraints:**
- A player cannot rate their own song (enforced in reducer)
- Hot seat can vote but their rating doesn't affect standings (enforced in logic)
- One rating per (rater, song) pair

**Lifecycle:**
- Created during VOTING state
- Used to calculate final scores at end of round
- Deleted when round ends (or kept for stats)

## Game Logic & State Machine

### State Flow

```
┌──────────────────────────────────────────────────────┐
│                   LOBBY                              │
│  • Players join with code                            │
│  • Host sees player list, clicks "Start Game"        │
│  • Host reduces room.state → SEED_SELECTION          │
│  • Select random hot seat player                     │
└────────────────────┬─────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────┐
│             SEED_SELECTION (60 sec)                  │
│  • Hot seat searches Spotify & picks a song          │
│  • Hot seat optionally enters a prompt               │
│  • Reduce: new Song (is_seed=true)                   │
│  • Reduce: transition to LISTENING                   │
└────────────────────┬─────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────┐
│           LISTENING (30 sec = preview length)        │
│  • All players hear the seed song                    │
│  • Clients auto-play the preview_url at same time    │
│  • Reduce: transition to SUBMISSION when done        │
└────────────────────┬─────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────┐
│           SUBMISSION (90 sec)                        │
│  • Non-hot-seat players search & submit 1 song each  │
│  • Reduce: insert Song for each submission           │
│  • Timer expires → transition to VOTING              │
└────────────────────┬─────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────┐
│            VOTING (per-song + 5 sec per)             │
│  • Each submitted song plays (30 sec)                │
│  • All players rate 1–10 (except submitter)          │
│  • Reduce: insert Rating for each vote               │
│  • Once all songs voted → transition to RESULTS      │
└────────────────────┬─────────────────────────────────┘
                     │
                     ▼
┌──────────────────────────────────────────────────────┐
│              RESULTS (10 sec)                        │
│  • Calculate round scores (average rating per song)  │
│  • Award points to submitters & hot seat             │
│  • Update Player.score                               │
│  • Show leaderboard to players                       │
│  • Reduce: reset for next round                      │
│  • If <2 players left → end game                     │
│  • Else → transition to SEED_SELECTION (loop)        │
└────────────────────────────────────────────────────────┘
```

**Scoring Rules:**
- A player's round score = average rating of their song × 10 (rounded)
  - E.g., if ratings are [7, 8, 9], average = 8, score = 80 points
- Hot seat score = average rating of all submitted songs (no individual song tied to them)
  - E.g., if songs got [7, 9, 6], hot seat earns (7+9+6)/3 = 22 points
- Cumulative score added to Player.score after each round

## Reducers (Game Logic)

Reducers are server-side functions that clients call. They modify state and can trigger other actions.

### `create_room(host_id: u64, host_name: String) -> Room`
Create a new game room.

**Preconditions:**
- host_id is a valid user (or generate a temporary ID)

**Postconditions:**
- New Room inserted with state=LOBBY, join_code generated
- New Player inserted for the host

**Error handling:**
- Return error if host_id already in another active room

---

### `join_room(join_code: String, player_name: String) -> Player`
A player joins an existing room.

**Preconditions:**
- join_code must exist
- room.state == LOBBY (no joining mid-game)

**Postconditions:**
- New Player inserted into the room

**Error handling:**
- Return error if code not found
- Return error if room is full (max 8 players, configurable)
- Return error if player already in room

---

### `set_ready(player_id: u64)`
Player toggles ready status (LOBBY only). Host waits for all players ready before starting.

---

### `start_game(host_id: u64, room_id: u64) -> Room`
Host initiates the game.

**Preconditions:**
- host_id is the host of room_id
- room.state == LOBBY
- At least 2 players in room

**Postconditions:**
- room.state = SEED_SELECTION
- Select a random player who hasn't been hot seat yet; if all have, reset cycle
- room.current_hot_seat_id = selected player
- room.state_changed_at = now

---

### `search_spotify(room_id: u64, query: String) -> Vec<SpotifyTrack>`
Search Spotify for songs. **This is the critical module that calls Spotify API with server-side credentials.**

**Preconditions:**
- query is non-empty
- room exists

**Implementation:**
```rust
#[reducer]
pub async fn search_spotify(
    ctx: &mut ReducerContext,
    room_id: u64,
    query: String,
) -> Result<Vec<SpotifyTrack>, String> {
    // Spotify Client Credentials token is stored in SpaceTimeDB config/env
    let token = get_spotify_token().await?; // Refresh if expired
    
    let url = format!(
        "https://api.spotify.com/v1/search?q={}&type=track&limit=5",
        urlparse::quote(&query)
    );
    
    let client = reqwest::Client::new();
    let res = client
        .get(&url)
        .header("Authorization", format!("Bearer {}", token))
        .send()
        .await?;
    
    let data: SpotifySearchResponse = res.json().await?;
    
    // Return simplified track objects to client
    Ok(data.tracks.items.iter().map(|t| SpotifyTrack {
        id: t.id.clone(),
        name: t.name.clone(),
        artist: t.artists[0].name.clone(),
        album_cover_url: t.album.images[0].url.clone(),
        preview_url: t.preview_url.unwrap_or_default(),
    }).collect())
}
```

**Return type:**
```rust
#[derive(Serialize, Deserialize, Clone)]
pub struct SpotifyTrack {
    pub id: String,
    pub name: String,
    pub artist: String,
    pub album_cover_url: String,
    pub preview_url: String,  // 30-sec MP3 URL, may be empty
}
```

**Error handling:**
- Return error if Spotify API rate-limited
- Return error if query is malformed
- Gracefully handle null preview URLs (return empty string, client shows "No preview")

---

### `submit_seed_song(room_id: u64, hot_seat_id: u64, spotify_track: SpotifyTrack, prompt: Option<String>) -> Song`
Hot seat submits the seed song.

**Preconditions:**
- room.state == SEED_SELECTION
- room.current_hot_seat_id == hot_seat_id
- prompt length ≤ 100 chars

**Postconditions:**
- New Song inserted with is_seed=true
- room.seed_song_id = new song ID
- room.seed_prompt = prompt
- room.state = LISTENING
- room.state_changed_at = now

**Error handling:**
- Return error if hot_seat_id is not current hot seat
- Return error if prompt too long

---

### `submit_song(room_id: u64, player_id: u64, spotify_track: SpotifyTrack) -> Song`
Non-hot-seat player submits a song.

**Preconditions:**
- room.state == SUBMISSION
- player_id != room.current_hot_seat_id
- No other song from player_id in current round

**Postconditions:**
- New Song inserted with is_seed=false

**Error handling:**
- Return error if player is hot seat
- Return error if player already submitted
- Return error if room not in SUBMISSION state

---

### `submit_rating(room_id: u64, rater_id: u64, song_id: u64, score: u8) -> Rating`
A player rates a song.

**Preconditions:**
- room.state == VOTING
- 1 ≤ score ≤ 10
- song.submitter_id != rater_id (can't rate yourself)
- song.round_number == room.current_round (rating correct round)

**Postconditions:**
- New Rating inserted
- Check if all songs have all votes; if so, auto-trigger `calculate_scores()`

**Error handling:**
- Return error if trying to vote on own song
- Return error if score out of range
- Return error if duplicate rating (upsert the old one)

---

### `calculate_scores(room_id: u64) -> void`
**Called automatically** when all votes are cast, or **manually triggered** by timeout.

**Logic:**
1. For each Song in current round:
   - Calculate average rating
   - Sum = average × 10 (e.g., avg 7.5 → 75 points)
   - Award to submitter

2. Hot seat score:
   - Average of ALL song ratings
   - Sum = average × 10
   - Award to hot seat player

3. Update Player.score for all

4. room.state = RESULTS
5. room.state_changed_at = now

**Pseudocode:**
```rust
#[reducer]
pub fn calculate_scores(ctx: &mut ReducerContext, room_id: u64) -> Result<(), String> {
    let mut room = get_room(room_id)?;
    let songs = query_songs_by_room_and_round(room_id, room.current_round);
    let ratings = query_ratings_by_room_and_round(room_id, room.current_round);
    
    for song in songs {
        let song_ratings = ratings.iter()
            .filter(|r| r.song_id == song.id)
            .map(|r| r.score as f32)
            .collect::<Vec<_>>();
        
        if !song_ratings.is_empty() {
            let avg = song_ratings.iter().sum::<f32>() / song_ratings.len() as f32;
            let points = (avg * 10.0).round() as u32;
            
            let mut submitter = get_player(song.submitter_id)?;
            submitter.score += points;
            update_player(submitter);
        }
    }
    
    // Hot seat score
    let all_ratings: Vec<u8> = ratings.iter().map(|r| r.score).collect();
    if !all_ratings.is_empty() {
        let avg = all_ratings.iter().map(|s| *s as f32).sum::<f32>() / all_ratings.len() as f32;
        let points = (avg * 10.0).round() as u32;
        
        let mut hot_seat = get_player(room.current_hot_seat_id.unwrap())?;
        hot_seat.score += points;
        update_player(hot_seat);
    }
    
    room.state = GameState::Results;
    room.state_changed_at = now();
    update_room(room);
    
    Ok(())
}
```

---

### `reset_for_next_round(room_id: u64) -> void`
Clean up the old round, prepare for the next. Called at the end of RESULTS state.

**Logic:**
1. Delete all Songs from current round (optional—keep for replay if desired)
2. Delete all Ratings from current round
3. Increment room.current_round
4. Select new random hot seat (or cycle through players)
5. room.state = SEED_SELECTION
6. room.state_changed_at = now

**Error handling:**
- If only 1 player left, end game (delete room or set state to ENDED)

---

### `leave_room(room_id: u64, player_id: u64) -> void`
A player leaves the room.

**Postconditions:**
- Delete Player record
- If room now empty, delete Room
- If room mid-game and player was hot seat, reassign hot seat (or pause)
- If room mid-game and player was only other player, end game

## Module Requirements

### Spotify API Integration

**Setup:**
1. Register an app at [Spotify Developer Dashboard](https://developer.spotify.com/dashboard)
2. Get `CLIENT_ID` and `CLIENT_SECRET`
3. Store in SpaceTimeDB config/environment (never hardcode credentials)

**Token Management:**
- Use Client Credentials OAuth2 flow to get an access token (lasts ~1 hour)
- Cache the token in SpaceTimeDB state; refresh if expired
- Retry on 401 Unauthorized

**Rate Limits:**
- Spotify limits to 429 when rate-limited
- Implement exponential backoff
- For a hackathon, per-user search throttle isn't necessary, but add a simple in-memory cache (last 10 searches) to avoid duplicate Spotify API calls

**Error Handling:**
- If Spotify is down, return a user-friendly error ("Search temporarily unavailable")
- If a preview URL is null, treat it as an empty string; client shows "No preview available"

**Scope needed:**
- Only `search` endpoint required (no user authentication needed)

## Development Setup

### Prerequisites
- Rust 1.70+
- SpaceTimeDB CLI (`cargo install spacetimedb-cli`)
- A Spotify Developer account (free)

### Local Development

1. **Initialize SpaceTimeDB project:**
   ```bash
   spacetimedb new music-party-backend --lang rust
   cd music-party-backend
   ```

2. **Copy schema & reducers** (from above) into `src/lib.rs`

3. **Add dependencies** to `Cargo.toml`:
   ```toml
   [dependencies]
   reqwest = { version = "0.11", features = ["json"] }
   tokio = { version = "1", features = ["full"] }
   serde = { version = "1.0", features = ["derive"] }
   serde_json = "1.0"
   chrono = "0.4"
   ```

4. **Run locally:**
   ```bash
   spacetimedb start --no-server  # Runs SpaceTimeDB locally
   ```

5. **In another terminal, deploy your code:**
   ```bash
   spacetimedb publish --project-path .
   ```

6. **Connect your React client:**
   ```typescript
   import { connect } from "@spacetimedb-sdk/react";
   
   await connect(
     "http://localhost:8000",
     "music_party_backend", // your module name
   );
   ```

2. Create a new project (gets a public URL)
3. Deploy:
   ```bash
   spacetimedb publish --project-path . --publish-token <your-token>
   ```

4. React client connects to the cloud URL instead of localhost

- Store Spotify `CLIENT_ID` and `CLIENT_SECRET` in SpaceTimeDB's secrets vault (not in code)
