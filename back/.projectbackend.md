Overview

Purpose: Backend for a fast-to-build, playable MVP of PassTheAux using SpaceTimeDB reducers for game logic and a server-side Spotify search proxy.
Constraints: Minimal surface area — implement only the reducers and tables needed for a playable loop (create/join → seed selection → submission → voting → results).
MVP Scope

Core features: room creation/join, hot-seat seed selection, preview play (30s), one submission per player, voting (1–10), scoring, next-round flow.
Omit for MVP: persistent replays, Elo ranking, spectator mode, advanced rate-limiting.
Minimal Schema

Room: id: u64, host_id: u64, join_code: String, state: GameState, current_round: u32, current_hot_seat_id: Option<u64>, seed_song_id: Option<u64>, state_changed_at: i64
Player: id: u64, room_id: u64, name: String, score: u32, is_host: bool, is_ready: bool, joined_at: i64
Song: id: u64, room_id: u64, round_number: u32, submitter_id: u64, spotify_id: String, name: String, artist: String, album_cover_url: String, preview_url: String, is_seed: bool, submitted_at: i64
Rating: id: u64, room_id: u64, round_number: u32, song_id: u64, rater_id: u64, score: u8, rated_at: i64
Indexes/constraints: index by room_id and round_number; enforce unique (rater_id, song_id).
Reducers (signatures & notes)

create_room(host_id: u64, host_name: String) -> Room: insert Room (LOBBY) and Player as host; generate 6-char join_code.
join_room(join_code: String, player_name: String) -> Player: only allowed when room.state == LOBBY; enforce MAX_PLAYERS_PER_ROOM.
set_ready(player_id: u64) -> Player: toggle is_ready.
start_game(host_id: u64, room_id: u64) -> Room: validate host, pick current_hot_seat_id, set state = SeedSelection, set timers client-side.
search_spotify(room_id: u64, query: String) -> Vec<SpotifyTrack>: server-side proxy; returns simplified tracks (id, name, artist, album_cover_url, preview_url).
submit_seed_song(room_id: u64, hot_seat_id: u64, track: SpotifyTrack, prompt: Option<String>) -> Song: validate hot seat and state; insert is_seed=true; set room.state = Listening.
submit_song(room_id: u64, player_id: u64, track: SpotifyTrack) -> Song: only during SUBMISSION; prevent duplicate submission by player for round.
submit_rating(room_id: u64, rater_id: u64, song_id: u64, score: u8) -> Rating: validate VOTING state, 1–10, not rating own song; upsert rating.
calculate_scores(room_id: u64) -> (): compute averages, award points (avg \* 10 rounded), award hot seat average of submissions, set state = RESULTS.
reset_for_next_round(room_id: u64) -> (): delete songs/ratings for round (optional), increment current_round, choose next hot seat, set state = SeedSelection.
leave_room(room_id: u64, player_id: u64) -> (): remove player; if host leaves reassign host; if room empty delete room.
Spotify integration

Auth flow: Client Credentials (server-side). Implement get_spotify_token() to call https://accounts.spotify.com/api/token with grant_type=client_credentials.
Token caching: store token + expiry in SpaceTimeDB config/state; refresh when expired.
Search: GET https://api.spotify.com/v1/search?q={}&type=track&limit=5. Map preview_url = null → "".
Resilience: on 429 or 5xx, return friendly error and retry with exponential backoff (small retry window for hackathon). Cache last 10 queries per room to avoid duplicate calls.

Secrets: store Spotify credentials in SpaceTimeDB secrets vault; never expose to client.
Authorization: validate player_id and host_id inside reducers. Only return room-scoped rows to subscribers.
Subscriptions: clients subscribe to filtered tables by room_id so each client only receives room updates.
